### 2.1 코드 정적 분석 결과

### 1. [MEDIUM] Kubernetes 컨테이너 권한 상승 방지 설정 미구성
- **심각도:** MEDIUM
- **판정:** False Positive
- **규칙 ID:** `yaml.kubernetes.security.allow-privilege-escalation-no-securitycontext.allow-privilege-escalation-no-securitycontext`
- **파일:** `k8s-minikube.yaml`
- **출처:** 코드 정적 분석

**설명:** frontend Deployment의 컨테이너에 `securityContext.allowPrivilegeEscalation: false`가 명시되지 않아, 컨테이너 내부의 setuid/setgid 바이너리 또는 취약한 프로세스가 권한 상승을 시도할 수 있는 기본 위험 구성이 남아 있습니다. 이는 일반적인 애플리케이션 입력 취약점이 아니라 컨테이너 런타임 하드닝 미흡으로 인한 권한 상승 위험입니다.

**오탐 판단 사유:**
> 현재 대화에서 실제 `k8s-minikube.yaml` 원본을 읽지 못해 해당 컨테이너에 `securityContext.allowPrivilegeEscalation`이 정말 누락되었는지 최종 검증은 불가합니다. 다만 제공된 스니펫상 `frontend` 컨테이너에 `securityContext`가 보이지 않아 Semgrep 경고 자체는 타당한 구성 누락 탐지입니다. 이 규칙은 사용자 입력 기반 공격이 필요한 취약점이 아니라 Kubernetes 하드닝 설정 누락 여부를 보는 정책성 점검이므로, 코드 상 방어 설정이 실제로 존재한다는 근거가 없으면 오탐으로 단정할 수 없습니다. 따라서 엄밀히는 파일 전체 확인이 필요하나, 현재 가시 범위 기준으로는 오탐 근거가 부족합니다.

**데이터 흐름 추적 (Taint Analysis):**
> 입력-출력 taint 분석 대상은 아니며, Kubernetes Pod/Container 보안 설정 누락 여부를 점검하는 정책성 이슈입니다. 제공된 스니펫에서는 `spec.template.spec.containers[].name: frontend` 아래에 `securityContext` 블록이 보이지 않으므로 기본 동작(allowPrivilegeEscalation 미명시) 상태로 해석됩니다. 이 경우 컨테이너 내부 프로세스가 setuid/setgid 바이너리 등을 통해 불필요한 권한 상승을 시도할 가능성을 차단하지 못합니다.

**공격 시나리오:**
> 공격자가 프론트엔드 컨테이너 내에서 RCE를 획득했거나 취약한 라이브러리를 악용해 셸 실행에 성공한 경우, `allowPrivilegeEscalation` 제한이 없으면 setuid/setgid 바이너리, 잘못된 파일 권한, 런타임 상의 보조 경로를 통해 컨테이너 권한을 더 높일 수 있습니다. 이후 호스트 마운트, 민감 정보 접근, 같은 노드 내 다른 워크로드 영향 확대가 가능해집니다.

**취약 원본 코드:**
```
spec:
  template:
    spec:
      containers:
        - name: frontend
          image: frontend:latest
          imagePullPolicy: ifNotPresent
          ports:
            - containerPort: 3000
          resources:
            requests:
              cpu: "100m"
              memory: "256Mi"
            limits:
              cpu: "500m"
              memory: "512Mi"
```

**수정 패치 코드 (Remediation):**
```
spec:
  template:
    spec:
      containers:
        - name: frontend
          image: frontend:latest
          imagePullPolicy: ifNotPresent
          securityContext:
            allowPrivilegeEscalation: false
            runAsNonRoot: true
            readOnlyRootFilesystem: true
            capabilities:
              drop:
                - ALL
          ports:
            - containerPort: 3000
          resources:
            requests:
              cpu: "100m"
              memory: "256Mi"
            limits:
              cpu: "500m"
              memory: "512Mi"
```

**수정 가이드:** 해당 컨테이너에 `securityContext`를 추가하여 권한 상승을 차단하십시오. 최소한 `allowPrivilegeEscalation: false`를 설정하고, 가능하면 `runAsNonRoot: true`, `readOnlyRootFilesystem: true`, `capabilities.drop: [ALL]`까지 함께 적용해 컨테이너 하드닝을 강화합니다. 이렇게 하면 컨테이너 내부에서 예상치 못한 privilege escalation 경로가 열리는 것을 줄일 수 있습니다.

**ISMS-P 위반 사항:**
> ISMS-P의 안전한 시스템 운영 및 접근통제/권한관리 원칙에 부합하지 않는 보안 설정 미흡으로 볼 수 있습니다. 다만 사용자가 제공한 ISMS-P 참조 문구는 개인정보 처리통지/제3자 제공 철회 등과 직접 연관된 조항으로, 본 Kubernetes 권한상승 설정 미비와는 직접 대응되지 않습니다.
