1. 🟠 평문 API 키가 .env에 노출됨

  • 심각도: HIGH
  • 판정: ✅ True Positive
  • 규칙 ID: generic.secrets.security.detected-generic-api-key.detected-generic-api-key
  • 파일: .env
  • 출처: Semgrep 탐지 → Agent 검증

설명: .env 파일에 SERPAPI_API_KEY가 평문으로 저장되어 있어 저장소 유출, 백업 유출, 배포 아티팩트 노출 시 즉시 외부 서비스 계정이 악용될 수 있습니다. 이 파일은 런타임 설정용 비밀정보 저장소로 사용되는 패턴이므로, 정적 분석 탐지 결과는 실제 취약점으로 판단됩니다.

🔄 데이터 흐름 추적 (Taint Analysis):

Source는 .env의 SERPAPI_API_KEY 평문 문자열입니다. main.py에서 load_dotenv()가 호출되어 환경변수로 주입될 수 있으며, 프로젝트 전체가 .env를 런타임 비밀값 소스로 취급합니다. Sink는 외부 API 호출에 사용될 수 있는 인증정보의 저장/배포/로그/이미지 노출이며, 이 값이 유출되면 SerpAPI 계정의 무단 사용과 과금 유발로 이어집니다.

💥 공격 시나리오:

공격자가 저장소, 배포 산출물, 컨테이너 이미지, 백업 파일 또는 CI 아티팩트를 획득하면 .env에서 SERPAPI_API_KEY를 확인할 수 있습니다. 이후 해당 키로 SerpAPI를 무단 호출하여 쿼리 비용을 발생시키거나 할당량을 소진시켜 서비스 장애를 유발할 수 있습니다. 추가로 검색 쿼리 패턴을 통해 내부 운영 방식이나 분석 관심사를 추정할 수도 있습니다.

2. 🟠 사용자 입력을 그대로 eval()에 전달하는 원격 코드 실행 취약점

  • 심각도: HIGH
  • 판정: ✅ True Positive
  • 규칙 ID: N/A
  • 파일: vuln-test-app\payment_api.js
  • 출처: Semgrep 탐지 → Agent 검증

설명: /api/eval 엔드포인트가 요청 바디의 mathFormula를 검증 없이 eval()에 전달합니다. 공격자는 임의의 JavaScript 코드를 실행시켜 서버 프로세스 권한으로 데이터 탈취, 명령 실행, 서비스 장애를 유발할 수 있습니다.

🔄 데이터 흐름 추적 (Taint Analysis):

Source: req.body.mathFormula (외부 사용자 입력) -> Sink: eval(mathFormula).
현재 입력값에 대한 화이트리스트 검증, 파싱, 샌드박스가 없으며 eval이 그대로 실행되므로, taint가 전혀 정화되지 않은 채 코드 실행 지점으로 도달합니다.

💥 공격 시나리오:

공격자는 /api/eval에 mathFormula=process.mainModule.require('child_process').execSync('id').toString() 같은 페이로드를 보내 서버에서 임의 명령을 실행하거나, 민감정보를 읽어 응답에 포함시킬 수 있습니다. 서비스가 고권한으로 실행 중이면 영향은 더 커집니다.

⚠️ 취약 원본 코드:

app.post('/api/eval', (req, res) => {
    const { mathFormula } = req.body;
    try {
        const result = eval(mathFormula);
        res.json({ result });
    } catch (e) {
        res.status(500).json({ error: "Calculation failed" });
    }
});

🛡️ 수정 패치 코드 (Remediation):

app.post('/api/eval', (req, res) => {
    const { mathFormula } = req.body;
    try {
        if (!/^[0-9+\-*/ ().]+$/.test(mathFormula)) {
            return res.status(400).json({ error: 'Invalid expression' });
        }
        const result = safeEvaluateArithmetic(mathFormula);
        res.json({ result });
    } catch (e) {
        res.status(500).json({ error: 'Calculation failed' });
    }
});

function safeEvaluateArithmetic(expr) {
    // 실제로는 검증된 수식 파서 사용 권장
    return Function(`"use strict"; return (${expr});`)();
}

수정 가이드: eval()을 제거하고, 수학식만 허용하는 검증 로직 또는 검증된 수식 파서를 사용해야 합니다. 임의 JavaScript 실행이 불가능하도록 입력 화이트리스트를 적용하고, 가능하면 별도 계산 라이브러리로 대체하십시오.

⚖️ ISMS-P 위반 사항:

ISMS-P 2.10.2의 비인가 접근 방지 및 보안설정 요구사항에 부합하지 않으며, 애플리케이션 취약점으로 인해 중요정보 유출 위험을 높입니다. 또한 안전한 암호/보안 코딩 관점에서도 위반 소지가 큽니다.

3. 🟠 MD5 기반 비밀번호 검증으로 인한 취약한 암호연산

  • 심각도: HIGH
  • 판정: ✅ True Positive
  • 규칙 ID: N/A
  • 파일: vuln-test-app\payment_api.js
  • 출처: Semgrep 탐지 → Agent 검증

설명: 로그인 로직이 비밀번호를 MD5로 해시하여 비교합니다. MD5는 충돌/사전대입 공격에 취약하고, 저장된 해시가 평문과 사실상 같은 수준으로 빠르게 노출될 수 있어 계정 탈취 위험이 큽니다.

🔄 데이터 흐름 추적 (Taint Analysis):

Source: req.body.password -> Sink: crypto.createHash('md5').update(password).digest('hex') 및 usersDB[username].passwordHash 비교.
사용자 입력 비밀번호가 약한 단방향 해시(MD5)로 처리되며, 솔트/반복/강한 KDF가 전혀 없어 오프라인 크래킹에 취약합니다.

💥 공격 시나리오:

공격자는 유출된 passwordHash를 사전/레인보우 테이블로 역추적해 admin / admin과 같은 약한 비밀번호를 즉시 복원할 수 있습니다. 이후 관리자 계정으로 로그인해 전체 자산을 조작하거나 권한을 상승시킬 수 있습니다.

⚠️ 취약 원본 코드:

const hash = crypto.createHash('md5').update(password).digest('hex');

🛡️ 수정 패치 코드 (Remediation):

const bcrypt = require('bcrypt');

app.post('/api/login', async (req, res) => {
    const { username, password } = req.body;
    const user = usersDB[username];
    if (!user) return res.status(401).json({ success: false, msg: 'Invalid credentials' });

    const ok = await bcrypt.compare(password, user.passwordHash);
    if (ok) {
        return res.json({ success: true, token: `fake-jwt-token-for-${username}` });
    }
    return res.status(401).json({ success: false, msg: 'Invalid credentials' });

수정 가이드: MD5를 폐기하고 bcrypt, scrypt, Argon2 같은 비밀번호 전용 KDF로 전환해야 합니다. 각 비밀번호는 고유 솔트를 사용하고, 저장된 해시는 강한 반복 비용을 적용해야 합니다.

⚖️ ISMS-P 위반 사항:

ISMS-P 2.6.7(암호연산) 위반 소지가 명확합니다. 취약한 해시 알고리즘 사용으로 인해 개인정보 및 계정 인증정보 보호가 미흡합니다.

4. 🟠 이체 로직의 IDOR 및 음수 금액 검증 부재로 인한 권한 우회/잔액 조작

  • 심각도: HIGH
  • 판정: ✅ True Positive
  • 규칙 ID: N/A
  • 파일: vuln-test-app\payment_api.js
  • 출처: Semgrep 탐지 → Agent 검증

설명: /api/transfer는 인증된 사용자와 fromAccount의 일치 여부를 검증하지 않고, amount가 양수인지도 확인하지 않습니다. 이로 인해 타인 계좌에서 무단 이체가 가능하고, 음수 금액을 이용해 잔액을 역전시키는 논리 조작이 가능합니다.

🔄 데이터 흐름 추적 (Taint Analysis):

Source: 요청 본문 fromAccount, toAccount, amount 및 헤더 x-user-id -> Sink: usersDB[fromAccount].balance -= amount; usersDB[toAccount].balance += amount;.
입력값이 인증/권한 검증 없이 이체 계산에 직접 사용되어, 계좌 소유권 검증이 누락된 상태로 자산 변경이 발생합니다.

💥 공격 시나리오:

공격자는 자신의 세션으로 요청을 보내면서 fromAccount=admin, toAccount=attacker, amount=1000을 넣어 관리자 잔액을 감소시킬 수 있습니다. 또는 amount=-10000을 전송해 출금 계좌 잔액을 증가시키고 수취 계좌 잔액을 감소시키는 식으로 잔액을 조작할 수 있습니다.

⚠️ 취약 원본 코드:

🛡️ 수정 패치 코드 (Remediation):

app.post('/api/transfer', authenticateSession, (req, res) => {
    const userId = req.user.id;
    const { fromAccount, toAccount, amount } = req.body;

    if (fromAccount !== userId) {
        return res.status(403).json({ error: 'Forbidden' });
    }
    if (!Number.isInteger(amount) || amount <= 0) {
        return res.status(400).json({ error: 'Invalid amount' });
    }
    if (!usersDB[fromAccount] || !usersDB[toAccount]) {
        return res.status(404).json({ error: 'Account not found' });
    }
    if (usersDB[fromAccount].balance < amount) {
        return res.status(400).json({ error: 'Insufficient balance' });
    }

    usersDB[fromAccount].balance -= amount;
    usersDB[toAccount].balance += amount;
    res.json({ success: true, msg: 'Transfer complete' });
});

수정 가이드: 서버 측 세션/토큰으로 사용자 식별을 확정하고, 요청의 출금 계좌가 로그인 사용자와 일치하는지 강제 검증해야 합니다. 또한 금액은 양의 정수만 허용하고, 계좌 존재 여부 및 잔액 검사를 이체 전에 엄격히 수행해야 합니다.

⚖️ ISMS-P 위반 사항:

ISMS-P 2.10.2의 비인가 접근 방지 및 권한 체계 통제 미흡에 해당할 수 있으며, 개인정보/자산의 무단 변경을 초래할 수 있습니다. 또한 접근권한 최소화 원칙에도 위배됩니다.

11. 🟡 비밀번호 검증에 MD5를 사용하여 취약한 인증 로직이 구현됨

  • 심각도: MEDIUM
  • 판정: ✅ True Positive
  • 규칙 ID: javascript.lang.security.audit.md5-used-as-password.md5-used-as-password
  • 파일: vuln-test-app\payment_api.js
  • 출처: Semgrep 탐지 → Agent 검증

설명: /api/login에서 사용자 입력 비밀번호를 MD5로 해시한 뒤 저장된 해시와 비교하고 있습니다. MD5는 비밀번호 해시 용도로 적합하지 않으며, 빠른 연산 속도와 salt 부재로 인해 사전 공격·브루트포스 공격에 취약합니다. 제공된 샘플의 admin / admin 고정 계정과 결합되면 계정 탈취 위험이 매우 높아집니다.

🔄 데이터 흐름 추적 (Taint Analysis):

Source: req.body.password → Processing: crypto.createHash('md5').update(password).digest('hex') → Sink: usersDB[username].passwordHash === hash 인증 결정. 외부 입력 비밀번호가 MD5로 단방향 해시되어 로그인 검증에 사용되며, 강도 높은 KDF(bcrypt/argon2)가 아니므로 오프라인 크래킹에 매우 취약합니다.

💥 공격 시나리오:

공격자는 로그인 API에 정상 계정명과 약한 비밀번호 후보를 대입하거나, DB/로그/백업에서 해시를 획득한 뒤 MD5 해시를 사전 공격으로 빠르게 역산할 수 있습니다. 샘플 데이터의 admin 해시는 흔히 알려진 MD5 값이므로 즉시 원문이 식별되어 관리자 계정 탈취로 이어질 수 있습니다.

⚠️ 취약 원본 코드:

const hash = crypto.createHash('md5').update(password).digest('hex');

if (usersDB[username] && usersDB[username].passwordHash === hash) {
    res.json({ success: true, token: `fake-jwt-token-for-${username}` });

🛡️ 수정 패치 코드 (Remediation):

const saltRounds = 12;

app.post('/api/login', async (req, res) => {

수정 가이드: MD5 기반 비밀번호 검증을 제거하고 bcrypt/argon2 같은 느린 비밀번호 해시 함수로 전환해야 합니다. 기존 계정은 로그인 성공 시 점진적으로 재해시하거나 일괄 마이그레이션해야 하며, 비밀번호 정책·속도 제한·계정 잠금·MFA를 함께 적용하는 것이 바람직합니다.

⚖️ ISMS-P 위반 사항:

ISMS-P 2.6.7(암호연산) 취지 위반: 취약한 해시 알고리즘(MD5)을 비밀번호 검증에 사용함. 또한 안전한 인증체계 요구사항에 부합하지 않음.
