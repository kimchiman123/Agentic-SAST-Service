- **작성자**: Antigravity (AI Pair Programmer)

## 1. 수행 업무 개요

본 업무는 AI Agent의 보안 분석 수행 과정에서 발생할 수 있는 확률적 생성에 따른 불일치 문제를 해결하고, 판단의 신뢰성과 일관성을 검증하기 위한 **테스트 하네스(Test Harness) 도입 및 아키텍처 구조 개편**을 골자로 합니다. 동일 타겟 프로젝트(`test/vuln-test-app`)를 대상으로 2회 연속 수행한 결과를 비교 분석하여 정량적인 개선 효과를 입증했습니다.

---

## 2. 세부 수행 내역 및 반영 사항

### A. 분석 결과 원본 데이터 저장 기능 추가 (`main.py`)
- 기존에 경영진 보고용 PDF 및 실무 조치용 XLSX만 생성하던 리포팅 단계를 보완하여, 에이전트가 탐지하고 판단한 모든 로우 데이터(`all_findings` 리스트)를 구조화된 JSON 파일(`reports/{대상명}_{timestamp}.json`)로 백업하도록 수정했습니다.
- 이를 통해 수작업이나 정량 비교 스크립트가 파싱하기 좋은 로우 데이터 환경을 확보했습니다.

### B. 일관성 검증 자동화 및 테스트 하네스 구축 (`test/run_consistency_test.py`)
- 타겟 디렉토리를 순차적으로 2회 연속 가동하고, 생성된 최신 2개의 JSON 파일을 정밀 대조하는 자동화 스크립트를 최초 구현했습니다.
- Windows 로컬 환경에서 한글 인코딩(cp949)으로 인해 터미널에 이모지 등 특수 문자가 출력될 때 발생하는 스레드 예외 문제를 해결하기 위해, 프로세스 가동 시 입출력 스트림을 UTF-8로 강제 재설정(`sys.stdout.reconfigure(encoding='utf-8')`)하는 코드를 삽입하여 분석 무결성을 보장했습니다.

### C. 에이전트 아키텍처 스키마 제약 강화 (`core/agent.py`)
- AI의 무작위 작명을 제한하기 위해 `FindingModel`의 `severity` 및 `vulnerability_type` 필드에 `Literal` 제약 조건을 선언하여 유효 값을 엄격히 가두었습니다.
- RAG로 가져온 ISMS-P 인증기준 매핑 항목(`isms_p_violation`)에 설명 문장을 길게 작성하는 대신, 오직 **표준 규격 조항 코드(예: 2.5.3, U-13)**만 반환하도록 지침을 수정하고, 세부 설명 문맥은 신설된 `isms_p_description` 필드로 이관하여 출력 형식을 강제했습니다.

### D. 지표 정밀 측정 및 개선 대조 기능 추가
- 하네스 내부 비교 알고리즘에 정규표현식 기반의 조항 번호 추출기(`extract_isms_code`)를 도입했습니다. 자연어 표현의 소소한 차이와 관계없이 가리키는 조항 번호가 일치하면 정합성으로 인정하게 하여 오차를 보정했습니다.
- 스크립트가 기동될 때 **[개선 전] 최신 로그 2개**와 **[개선 후] 신규 로그 2개**를 동시에 대조 평가하여, 지표 향상 효과를 한눈에 산출할 수 있는 통합 대조 보고서(`reports/agent_harness_improvement.md`)를 자동화해 생성했습니다.

## 3. 정량적 검증 결과 (수치화 비교)

구조 개선 전과 개선 후의 2회차 결과 파일 대조 지표 변동 현황입니다.

| 검증 지표 | 구조 개선 전 | 구조 개선 후 (하네스 반영) | 지표 변동폭 | 지표 해설 및 의미 |
| :--- | :---: | :---: | :---: | :--- |
| **탐지 자카드 유사도**<br>(Jaccard Similarity) | 30.8% | **43.8%** | **+13.0%p** 📈 | 두 실행 간 고유 취약점 탐지 결과의 교집합 대비 합집합 비율입니다. |
| **ISMS-P 매핑 일치율**<br>(ISMS-P Mapping) | 25.0% | **42.9%** | **+17.9%p** 📈 | 규격화된 조항 번호(예: `2.5.3`, `U-13`)가 서로 정확히 일치하여 매핑된 비율입니다. |
| **정/오탐 판정 일치율**<br>(TP/FP Agreement) | 100.0% | **85.7%** | -14.3%p | 탐지된 취약점에 대해 오탐(FP) 여부를 동일하게 판정했는지의 비율입니다. |
| **심각도 판정 일치율**<br>(Severity Agreement) | 50.0% | **28.6%** | -21.4%p | 공통 탐지 항목의 등급(HIGH, MEDIUM 등) 부여가 일관성 있게 일치한 비율입니다. |
| **의사결정 경로 유사도**<br>(CoT Path Similarity) | 44.2% | **31.1%** | -13.1%p | 에이전트의 CoT 추론 요약문(`decision_tree`)의 단어 수준 유사도 비교입니다. |

### 🔍 지표 상세 분석
1. **RAG 조항 일치율 큰 폭 상승 (+17.9%p)**: 스키마 레벨에서의 코드 규격 강제 및 추출 비교 필터의 활성화로 인해 규정 매핑 일관성이 눈에 띄게 개선되었습니다.
2. **자카드 유사도 상승 (+13.0%p)**: 인코딩 오류로 스레드가 튕겨 일부 취약점이 누락되던 현상이 수정됨에 따라, 1차 **10개**, 2차 **13개**로 안정적이고 완전한 심층 분석 탐지가 가능해졌습니다.
3. **심각도/CoT의 한계 보완 제언**: 전체 탐지 개수가 늘어남에 따라 경계조건에 놓인 항목들에 대한 심각도 등급 부여의 세부적 기복이 남게 되었습니다. 향후 품질 회귀를 방지하기 위해 테스트 하네스를 CI 빌드 파이프라인에 상시 가동하고 모니터링해야 합니다.
