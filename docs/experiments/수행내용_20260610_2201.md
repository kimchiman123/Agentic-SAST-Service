## 2. 3차 최종 평가 (gpt-5.4, top-3 검색) 지표 분석

### ① `context_recall` 하락 (0.1778 → 0.0000)
* **원인:** 토큰 절약 및 속도 개선을 위해 RAG 검색 결과 반환 수를 기존 `n_results=8`에서 `n_results=3`으로 축소하여 투입했습니다.
* **결과:** 검색 후보 문서 풀이 좁아지면서 그나마 "경쟁 조건(TOCTOU)" 가이드 내용에 미세하게 걸쳐 있었던 일부 지침 청크가 검색 결과 상위 3개에서 완전히 밀려나 유실되었습니다. 이로 인해 RAG 검색 결과 내에 `ground_truth`의 핵심 문장과 매핑되는 정보가 물리적으로 0이 되어 Recall이 `0.0000`으로 복귀하게 되었습니다.

### ② `context_precision` 상승 (0.0833 → 0.3333)
* **원인:** 검색 문서 수를 8개에서 3개로 압축하면서 검색 데이터의 모호성(노이즈)이 줄어들었습니다. 가져온 3개의 청크 중 1개 정도가 질문과 연관된 조항(예: 2.8.1 등)으로 상위에 잘 배치된 것으로 인식되어 정밀도가 향상되었습니다.

### ③ `answer_relevancy` 상승 (0.7776 → 0.8569)
* **원인:** `gpt-5.4` 모델이 RAG에서 검색된 컨텍스트를 조리 있게 활용하여 질문에 대해 구조적이고 정확한 답변을 출력하는 능력(`answer_relevancy`)이 우수함을 보여줍니다.

## 3. 신규 모델(gpt-5.5 / gpt-5.4) 평가 진행 시 트러블슈팅 일지

RAGAS 프레임워크와 신규 출시 모델(gpt-5.5 / gpt-5.4)을 연계하여 평가할 때 발생한 예외 상황 및 극복 조치 사항을 기록합니다.

### ① tiktoken 라이브러리 매핑 오류 (gpt-5.5 / gpt-5.4 공통)
* **문제 상황:** 신규 모델명이 입력되었을 때 토큰 수 계산 라이브러리인 `tiktoken`이 모델 정보 자동 매핑에 실패하여 `Could not automatically map model to a tokeniser` 예외가 발생했습니다. RAGAS 내부 비동기 루프에서 이 예외를 캐치하지 못해 프로세스가 영구 멈춤(Hang) 상태가 되었습니다.
* **조치 사항:**
  1. LangChain 생성자에 `tiktoken_model_name="gpt-4o"` 설정을 명시해 주어 랭체인 차원의 에러를 방어했습니다.
  2. RAGAS 라이브러리 내부에서 독립적으로 `tiktoken.encoding_for_model`을 호출하는 부분까지 완벽히 우회하기 위해, 스레드 실행 전 `tiktoken.encoding_for_model` 함수가 신규 모델명을 입력받았을 때 `gpt-4o` 인코딩을 반환하도록 **몽키 패치(Monkey Patching)** 처리하여 해결했습니다.

### ② gpt-5.5 모델의 temperature 매개변수 에러 (400 BadRequest)
* **문제 상황:** `gpt-5.5`는 추론 최적화 모델 특성상 `temperature` 파라미터로 `1.0` 이외의 온도를 지원하지 않아, RAGAS가 내부적으로 성능 측정을 위해 온도를 `0.01` 또는 `0.3`으로 주입해 API를 전송할 때 `BadRequestError` 400 에러를 반환하며 점수가 전부 `NaN`으로 깨지는 현상이 발생했습니다.
* **조치 사항:**
  * `openai.resources.chat.completions.Completions.create` 함수를 몽키 패치하여, API 전송 직전에 `temperature` 인자 값을 `1.0`으로 가로채 강제 변경하여 발송하도록 처리해 400 에러를 원천 차단했습니다.
  * (최종적으로는 `temperature`를 완전 지원하는 `gpt-5.4` 모델과 `temperature=0` 조합을 사용하여 안정적인 분석 궤도를 복구하였습니다.)
